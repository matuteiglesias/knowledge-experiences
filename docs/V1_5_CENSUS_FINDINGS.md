The all-E0 V1.5 snapshot has now been crossed: cases #8 and #9 reached E3 using trusted live LCD source evidence. #8 materialized 19 public institutional pages; #9 reused the same source release and required configuration/curation only. # V1.5 — Census findings and stop decision

## Finding 1 — V1 mechanics are ahead of real-source adoption

V1.1–V1.4 proved deterministic composition, a Paper KB catalog seam, author reuse, an external Abstract Scroller handoff and a non-paper LCD adapter. Those proofs are valuable, but they use sanitized or contract-check material. Under the original maturity rules, none of the fifteen named experiences has yet earned E1 from a concrete approved real source release.

The correct response is not to relax the maturity definition. It is to use the system.

## Finding 2 — marginal cost is already falling

The strongest composability evidence is structural:

- author navigation reused the same Paper KB release/renderer with facet configuration;
- LCD reused the same generic selection and static renderer with only a bounded source adapter;
- Abstract Scroller stayed externally owned while the compositor added only a pinned handoff;
- Thesis and Journal were recognized as vertical exceptions instead of triggering replatforming work.

This is the intended economic property of the repo: repeated experiences should buy less new software.

## Finding 3 — strongest V2 candidate: curator-controlled groups/order

Three independent observations point in the same direction:

1. Economic-complexity reading path wants a deliberate sequence.
2. Course readings commonly want modules/groups plus order.
3. The existing Thesis portal already demonstrates curated research trails as useful vertical semantics.

This is enough to promote `ordered-groups-and-reading-trails` from a vague idea to a **candidate**, but not enough to implement it before one real composed collection forces the exact shape.

## Finding 4 — second V2 frontier: mixed-source membership

Personal publications and policy/research dossiers both require more than one source authority. The dossier also raises selection-provenance questions. This repeats enough to deserve a named frontier: `multi-source-collections-and-curation-receipts`.

Still do not implement a generic union/orchestrator yet. First attempt a small real two-authority collection and record identity collision, provenance and regeneration behavior.

## Finding 5 — several apparent platform gaps are correctly local

- working-paper series is upstream metadata quality/authority;
- LCD per-record content hashes do not yet justify a core provenance field because source-file SHA already freezes the release;
- selected review snapshots do not justify downstream reconstruction of Paper KB review records;
- Knowledge Inspect and KB Artifacts remain optional capabilities until an experience needs their semantics;
- Journal publication policy belongs to the parked editorial frontier.

## Stop decision

**V1 is complete as an architecture/proof programme after this census. Do not start a broad V2 build now.**

The next operating regime is:

```text
approved real source
      ↓
compose with existing V1
      ↓
observe actual friction
      ↓
add only the smallest repeated capability
```

A V2 PR becomes justified when a concrete real-use run makes one of the two repeated candidates unavoidable. Until then, architecture development has lower expected value than materializing real experiences.
